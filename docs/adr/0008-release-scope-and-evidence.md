# ADR-0008: Scope релиза 1.0 и протокол доказательств

- **Status:** Accepted 2026-10-18 (решения D1–D7 владельца)
- **Date:** 2026-10-18
- **Supersedes:** ADR-0006 (bounded validation governance)
- **Amends:** ADR-0007 (гейт `auto`)

## Контекст

Проект накопил ~100 КБ governance-документов, восемь «гейтов», роли Operator/
Adjudicator и маршрутизацию по моделям, при этом ни одна аппаратная ячейка не
закрыта, а режим `auto` не включает HDR без тестовой env-переменной. Правила
не соблюдаются самим кодом (приватный API, критерий HDR, строки UI). Нужен
минимальный набор правил, который один владелец с одной машиной на стенд
может реально исполнять, не теряя оракулов, которые находили реальные дефекты.

## Решение

1. Upstreaming не является целью релиза; цель — мержабельность с upstream
   `main` (процедура `upstream-diverge:`). `brand:`-коммиты отменены.
2. Гейт `auto` — runtime-критерий: композитор объявляет `wp_color_manager_v1`,
   GTK color management активен, монитор под окном в HDR, caps достаточны.
   Тестовый override `CINEHDR_FORCE_SURFACE_SUBMISSION` из продукта удаляется.
   Приёмка — два независимых оракула (`AGENTS.md` §8): L3p — протокольная
   трасса показывает на поверхности, несущей видео, описание цвета, которое
   парсер распознаёт как HDR по семантике используемой версии протокола
   (распознаваемые варианты имеют положительный и отрицательный контроль;
   нераспознанное — UNCLEAR), и commit; `failed` оценивается по проверяемой цепочке описания,
   `wl_display.error` на соединении проверяемой поверхности исключает PASS;
   L4 — визуальная приёмка по заранее заданным критериям (различимость
   ступеней, клиппинг) против эталона, подтверждённого по его фактическому
   выходному пути (API/контекст + L3p его поверхности), с исходами
   PASS/FAIL/UNCLEAR и без заявления о колориметрической точности.
3. `GDK_DEBUG=color-mgmt` включён по умолчанию в Flatpak-лаунчере (GTK runtime
   пиннован), opt-out `CINEHDR_NO_COLOR_MGMT=1`; нативная сборка — opt-in.
4. Governance сводится к `AGENTS.md` (старые документы подлежат удалению по PLAN C1 после C0); доказательства — уровни L1, L2, L3, L3p,
   L4 и правила их силы в `AGENTS.md` §8. Статусы — в `docs/TESTING.md`.
5. Scope 1.0: Flatpak x86_64, Wayland; HDR для GNOME ≥ 48 и Plasma ≥ 6.3;
   X11 и прочие композиторы — SDR; gpu-next — экспериментально, по умолчанию
   выключен; нативная сборка — best effort.
6. Fork-строки переводятся через `update_translations.sh` в `i18n:`-коммитах.
7. Валидационные инструменты выносятся из устанавливаемого продукта в
   `tools/validation/` и сохраняются в объёме: парсер Wayland-трассы с
   тестами; пиксельный оракул FBO с отрицательными контролями; минимальный
   автосценарий «SDR → HDR → SDR на паузе + первый опубликованный кадр +
   корректное завершение»; минимальный автоэкспорт диагностического снимка
   для этого сценария. Сборщик фактов (`collect_video_output_facts`,
   `build_video_output_report`) остаётся в продукте. Точки подключения
   измерений в продукте сохраняются (измерение того же FBO в момент
   публикации) и по умолчанию выключены. Критерий сохранения любого
   механизма: защищает актуальный инвариант и выявляет конкретный дефект —
   исторический либо намеренно внесённый отрицательный контроль. Прочие
   механизмы удаляются только адресно, по одному на коммит, с указанием
   потерянной защиты и её замены или причины ненужности.

## Отвергнутые альтернативы

- Сохранить ADR-0006 с attempt-families и HOLD-rows: не исполняется на
  практике, не даёт пользователю HDR.
- Оставить `auto` закрытым до протокольного доказательства per-frame
  submission: GTK такого доказательства не предоставляет; критерий недостижим.
- Принимать HDR только по визуальному сравнению: нефальсифицируемо на
  композиторах с собственным тон-маппингом; нужен независимый протокольный
  оракул. Принимать только по трассе: трасса не доказывает применение
  описания композитором.
- Требовать колориметр для приёмки: избыточно для релиза плеера.
- Удалить валидационную инфраструктуру целиком: теряются оракулы, нашедшие
  реальные дефекты (перечень — `tools/validation/README.md`); ручной Copy
  Report не фиксирует состояние первого кадра.

## Последствия и риски

- На композиторах, где GTK молча конвертирует HDR-описание в SDR, `auto` даст
  картинку хуже тон-маппинга mpv. Страховка — `force-sdr` и причина в
  диагностике.
- Утверждения о цветовой точности не делаются; только «HDR доставлен /
  не доставлен / неясно» по двум оракулам.
- Инструменты в `tools/validation/` требуют сборки с `validation=true` и
  поддержки точек подключения в продукте; это осознанная цена сохранения
  регрессионных проверок.

## Откат

Вернуть env-гейт в `hdr_detection` и `GDK_DEBUG` в opt-in; остальные пункты —
документальные и отката не требуют.

## Измеримая валидация

Все критерии `docs/PLAN.md` §8 выполнены; ячейки `docs/TESTING.md` для
GNOME-AMD — PASS по L3p и L4; автосценарий `publication` PASS на релизном
коммите.
