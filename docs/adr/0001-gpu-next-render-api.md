# ADR-0001: Рендер-бэкенд GPU Next через Render API libmpv

- **Original title:** GPU Next through a pinned libmpv Render API backend
- **Status:** Accepted (сокращён до 1 страницы по C12 / ADR-0008; исходный прототип: 2026-08-19)
- **Date:** 2026-08-19 (редакция 2026-10-24)
- **Scope:** Экспериментальный бэкенд `gpu-next` (`opengl-next`)
- **Полная историческая версия:** `git show e7d696c2d672e7c1e06408dd9ada624b2dad488b:docs/adr/0001-gpu-next-render-api.md`

## Контекст

CineHDR встраивает mpv через libmpv OpenGL Render API. Апстримный libmpv не предоставляет релизного бэкенда для `gpu-next` в Render API (mpv issue #10810). Для доступа к возможностям libplacebo (включая обработку метаданных Dolby Vision) используется экспериментальный API `opengl-next` на базе пиннованного патча mpv (коммит `97179bce7`).

Архитектурная граница рендера остаётся неизменной:

```text
mpv decode / libplacebo
  -> CineHDR GL framebuffer (GL_RGBA16F для HDR, GL_RGBA8 для SDR)
  -> Синхронизация GL (пул буферов, sync fence, destroy-notify)
  -> Gdk.GLTexture (Rec.2100 PQ или sRGB color state)
  -> GTK4 / Wayland compositor
```

CineHDR сохраняет полный контроль над FBO, временем жизни текстур и цветовыми тегами GDK, не передавая управление окном или swapchain библиотеке mpv.

## Решение

1. **Бэкенд по умолчанию — `legacy` (`opengl`)**: Стабильный проверенный путь остаётся основным и работоспособным. Бэкенд `gpu-next` (`opengl-next`) является строго экспериментальным, выключен по умолчанию и исключён из обязательных критериев релиза 1.0 (D5 / ADR-0008).
2. **Выбор бэкенда фиксирован на процесс**: Бэкенд выбирается при запуске процесса (настройка GSettings/аргументы) и не меняется на лету во время воспроизведения.
3. **Fallback только при создании контекста**: Откат с `gpu-next` на `legacy` допустим исключительно на этапе инициализации `mpv_render_context_create()`. При ошибках во время активного рендера хот-свап запрещён: фиксируется статус ошибки и запрашивается чистый перезапуск приложения в `legacy`.
4. **Изоляция и пиннование зависимостей**: Кастомный libmpv собирается в изолированном префиксе или Flatpak-окружении с фиксированными ревизиями mpv, libplacebo и FFmpeg. Системный libmpv не модифицируется.
5. **Защита жизненного цикла GL-контекста**: При пересоздании контекста `Gtk.GLArea` вызов `mpv_render_context_free()` в `opengl-next` сбрасывает видеоцепочку (`kill_video_async()`, `vid=no`). CineHDR сохраняет выбор видеодорожки и восстанавливает её (`vid=no` → `vid=auto`/track ID) после создания нового контекста Render API.
6. **Запрет неподтверждённых заявлений о Dolby Vision**:
   - Profile 5 (`IPTPQc2`) принудительно направляется в SDR tone mapping mpv (`DOVI_UNSUPPORTED_PROFILES = (5,)`), в том числе при `force-hdr`.
   - Наличие бэкенда `opengl-next` само по себе не является доказательством корректности DoVi; поддержка Profile 5 запрещена к включению без отдельной инструментальной валидации reshaping и точности цвета.
   - CineHDR выводит растрированный кадр Rec.2100 PQ в FBO; это не является сквозной передачей (passthrough) или полной поддержкой Dolby Vision FEL.

## Последствия

- **Стабильность**: Основной путь воспроизведения (`legacy`) полностью защищён от изменений в экспериментальном бэкенде.
- **Согласованность со Scope 1.0 (ADR-0008)**: Старые многоэтапные «гейты» (Gate 0–4, 2W) заменены доказательной моделью уровней L1–L4 (TESTING.md / AGENTS.md §8) и единым авто-гейтом Wayland.
- **Ограничения**: Поддержка DoVi Profile 5 остаётся заблокированной в коде контроллера; RPU профилей 7/8 трактуется как экспериментальный рендер в Rec.2100 PQ.
- **Откат**: Переключение настройки в `legacy` или запуск со стандартным системным libmpv мгновенно возвращает плеер на проверенный тракт без миграции данных.
- **История**: Подробная история обсуждения, черновики гейтов и промежуточные логи доступны командой:
  `git show e7d696c2d672e7c1e06408dd9ada624b2dad488b:docs/adr/0001-gpu-next-render-api.md`
