# ADR-0004: Пиксельная валидация FBO (FBO pixel oracle)

- **Original title:** Gate 2 embedded-FBO pixel validation
- **Status:** Accepted (сокращён до 1 страницы по C12 / ADR-0008; исходный вариант: 2026-08-23)
- **Date:** 2026-08-23 (редакция 2026-10-24)
- **Scope:** Автономная валидация рендера в FBO CineHDR
- **Builds on:** [ADR-0001](0001-gpu-next-render-api.md) (исторически также ADR-0003, см. git show 0d3d57a:docs/adr/0003-pinned-gpu-next-flatpak-stack.md)
- **Полная историческая версия:** `git show d314c5d:docs/adr/0004-gate2-fbo-pixel-validation.md`

## Контекст

Скриншоты оконной системы (GTK/Wayland) непригодны в качестве первичного оракула рендерера, так как смешивают работу libmpv, цветовое состояние GDK, преобразования композитора и калибровку дисплея. Стандартная команда mpv `screenshot` также не гарантирует считывание именно того FBO, которым владеет CineHDR и который публикуется в GTK.

Для отделения ошибок рендерера от эффектов декодера и оконной системы необходим детерминированный оракул, считывающий пиксели непосредственно из FBO CineHDR через `glReadPixels` в момент публикации кадра.

## Решение

1. **Контракт FBO CineHDR**: Рендеринг выполняется в FBO под управлением CineHDR: `GL_RGBA16F` (depth 16) для HDR (Rec.2100 PQ) и `GL_RGBA8` (depth 8) для SDR (sRGB). Считывание через `glReadPixels` выполняется строго после ребинда клиентского FBO.
2. **Идентичные входы для сравнения**: Сравнение рендереров (`legacy` и экспериментального `gpu-next`) или сценариев переключения производится на сгенерированных lossless-паттернах (FFV1 RGB или HEVC Main 10 YUV 4:2:0) с фиксированными параметрами, размерами, таймстампами и опциями. Изменяемым параметром является только исследуемый фактор.
3. **Строгое происхождение (provenance) и отказ при пропусках (fail-closed)**:
   - В артефактах валидации фиксируются хэши фикстур, версия генератора, точные ревизии mpv, libplacebo, FFmpeg, видеокарта и драйвер.
   - Любые пропуски кадров, неполные FBO, отсутствующие зависимости, неожиданные API или нечисловые/NaN сэмплы являются строгой ошибкой (`FAIL`), а не поводом для пропуска теста.
4. **Границы доказательства**:
   - Оракул FBO подтверждает только корректность формирования пикселей во внутреннем FBO CineHDR и его формат.
   - Измерение FBO **не доказывает** передачу HDR-описания композитору Wayland и физический вывод HDR дисплеем (GDK texture publication ≠ compositor submission ≠ display output).
   - Исторический Gate 2 и экспериментальный бэкенд `gpu-next` **не являются** обязательными критериями релиза 1.0 (D5 / ADR-0008). Доказательная база релиза строится на уровнях L1–L4 (AGENTS.md §8, TESTING.md).

## Последствия

- **Сохранение в составе инструментов (D7)**: По ADR-0008 пиксельный оракул FBO с отрицательными контролями и точки подключения измерений сохранены для защиты от регрессий (дефект старых HDR-пикселей на паузе). В настоящий момент `PausedTransitionPixelOracle` находится в `src/gpu_validation.py`, а его перенос в `tools/validation/` запланирован по C4a.
- **Разделение слоёв**: Возможные расхождения между `legacy` и `gpu-next` (тон-маппинг, дизеринг) документируются как дельты, но не блокируют стабильный тракт.
- **Откат**: Отключение оракула или удаление тестового раннера не влияет на основной код плеера CineHDR; точки подключения в продукте по умолчанию пассивны (`None`).
