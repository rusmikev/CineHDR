# CLAUDE.md

Правила проекта живут в **`AGENTS.md`** — это единственный источник правил. Прочитай его
целиком до первого действия; он главнее твоих предположений об API и исторических
комментариев в коде. Этот файл только вводит в проект и фиксирует специфику работы
Claude Code. Правила здесь не дублируются, чтобы не расходиться с `AGENTS.md`.

## Проект

CineHDR — форк видеоплеера [Cine](https://github.com/diegopvlk/Cine)
(GTK4 / libadwaita / libmpv / Python + ctypes) с HDR-выводом на Wayland:
mpv → FBO `RGBA16F` → `GdkGLTexture` с `GdkColorState` → GSK → `wp_color_manager_v1`.

- Цель: релиз 1.0, Flatpak x86_64. Нативный HDR на GNOME ≥ 48; на KDE Plasma ≥ 6.7
  документированный SDR-fallback (решение D8); SDR везде, где работает Cine.
- Проверено на железе только GNOME/AMD. Остальные ячейки — `NOT_RUN`
  (`docs/TESTING.md`). Репозиторий — публичная витрина владельца (D14): честный scope,
  английские README и CHANGELOG.
- У тебя нет GPU, Wayland и HDR-монитора. Аппаратные проверки делает владелец по
  блоку «Проверка на железе» (`AGENTS.md` §8). Результат, которого ты не видел, не
  утверждай.

## Команды

```bash
meson setup build                              # один раз
meson test -C build --print-errorlogs
ruff check src tests tools
python3 run_dev.py /path/to/video.mkv          # smoke — выполняет владелец
```

Какие проверки нужны перед коммитом, зависит от типа изменения: `AGENTS.md` §2 и §17.

## Что важно помнить (подробности в AGENTS.md)

- Рендер-путь (`video_widget.py`, `gl_renderer.py`, `gl_bindings.py`,
  `hdr_controller.py`): правки только по инвариантам §4 и с аппаратным smoke владельца.
- API не выдумывать и приватный API не использовать (§6); логи и UI только на английском (§7).
- Новые файлы, модули, документы, ключи настроек — только при названной потребности (§10);
  новые файлы в корне и новые governance-документы без разрешения запрещены.
- Статусы ячеек `TESTING.md` и задач `PLAN.md` обновляешь ты; тексты и критерии задач,
  `AGENTS.md`, `GEMINI.md` — только по прямому поручению владельца.

## Работа Claude Code в этом репозитории

- **Модель.** По политике владельца (`~/.claude/CLAUDE.md`) сессия на Sonnet. Шаг на Opus —
  только с согласия владельца, с предупреждением «этот шаг прошу запустить на Opus: <причина>».
- **Экономия лимитов.** Мелкая задача: разработчик и ревьюер, без плана и тестировщика.
  Воркфлоу и параллельные агенты — только по явной просьбе. Диффы и большие файлы целиком
  не читай; для широкого поиска по коду бери дешёвого агента.
- **Git.** Работа в ветке `task/<короткое-имя>` от `main`. Коммиты однотемные, до ~400 строк,
  с префиксами из §12. В конце сообщения — строки авторства, которые задаёт среда сессии.
  `push`, PR, теги и правки remote — только с явного разрешения владельца.
- **Отчёт** по задаче — строго формат `AGENTS.md` §15, раздел «НЕ проверено» обязателен.
- **Конец сессии.** Окно разрослось или лимит исчерпан: обнови статус задачи в `docs/PLAN.md`,
  кратко передай ветку, HEAD, сделанное, непроверенное и следующий шаг, предложи новую сессию.
- **Рабочее дерево.** Каталоги `build*`, `repo`, `.worktrees`, `.local`, `validation-reports`,
  `tmp`, `*.flatpak`, `*.patch` — локальные и в git не попадают. Не коммить их и не читай
  без необходимости.
